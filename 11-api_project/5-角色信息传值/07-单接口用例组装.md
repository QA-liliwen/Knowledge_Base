# 单接口用例组装（build_test_item_cases）

## 实现内容

把选中的 type1 测试项逐条展开成 pytest 可消费的用例列表：接口 URL 用 domain/env 拼全、按"测试项配置的角色 + 端"从预组装头表**查整头**、用例字段平铺成一条执行记录。角色传值在单接口通道的"落地动作"就在这里——用例自身不存 token，只配置角色/端两个字段，执行时查表取整头。

## 代码来源

`api_app/api_test/api_executor.py`（L30-53）

---

## 第一部分：函数整体

```py
# 合并多个测试项的用例数据（请求头从全量预组装表中查表获取，不依赖逐项现拼）
def build_test_item_cases(test_item_ids, domain, env, headers_map):
    all_cases = []
    for item_id in test_item_ids:
        test_item = DB_TestItem.objects.get(id=item_id)
        interface = test_item.interface
        base_url = "https://" + interface.url.format(domain, env)
        # 该测试项的请求头：直接取角色×端对应整头（查不到降级空头）
        headers = headers_map.get(f"user_{test_item.role}_{test_item.system}") or {}
        for case in test_item.cases:
            all_cases.append({
                'url': base_url,
                'method': interface.method.upper(),
                'headers': headers,
                'CaseID': case['CaseID'],
                'case_name': case['case_name'],
                'is_active': case['is_active'],
                'body': case['body'],
                'expected_status_code': case['expected_status_code'],
                'assertions': case['assertions'],
                'description': case['description'],
                'sql_database': test_item.sql_database,  # SQL 断言查询库名
            })
    return all_cases
```

**关键点**：

- 三个入参：测试项 id 列表（type1 子集）、domain/env 字符串段、`headers_map`（06 篇预组装产物）。
- 双层展开：外层测试项、内层用例——一个测试项可含多条用例，全部平铺进一个列表。
- 产出的 `all_cases` 长度就是执行总数（dispatch_run 里回填 `test_run.total`），最终序列化进 `{run_id}_cases.txt`（见 08）。

## 第二部分：URL 拼装

```py
test_item = DB_TestItem.objects.get(id=item_id)
interface = test_item.interface
base_url = "https://" + interface.url.format(domain, env)
```

**关键点**：

- `interface.url` 是**双空占位符模板**，实测样例：`{}/qbank/{}/exam/exam/listExams`——两个 `{}` 按顺序被 `domain`、`env` 填充。
- 实参来自 dispatch_run 的 `domain_obj.domain`（如 `devapi1.lingshi.com`）与 `env_obj.env`（如 `vs2`），拼出 `https://devapi1.lingshi.com/qbank/vs2/exam/exam/listExams`。
- 接口模板只维护一份、跨环境复用：同一测试项切换环境/域名不需要改任何配置。
- `method` 用 `.upper()` 规范化（配置里可能大小写混写）。

## 第三部分：角色头查表（角色传值落地）

```py
# 该测试项的请求头：直接取角色×端对应整头（查不到降级空头）
headers = headers_map.get(f"user_{test_item.role}_{test_item.system}") or {}
```

**关键点**：

- 与 06 篇的产键规则**严格对称**：06 生产 `user_{role}_{system}`，此处按测试项配置的 `role`/`system` 消费。
- `or {}` 双重兜底：测试项角色未在环境配置账号（或角色/端为空）→ 查不到 → 降级空头，请求裸发、自然 401，不拦截执行。
- 测试项只存"角色 + 端"两个**英文值**字段，token 在执行时才注入——**配置与凭证解耦**：改账号不动测试项。
- 同一测试项的所有用例**共用同一个 headers dict 引用**（不深拷），序列化时各自展开，无副作用且省内存。

## 第四部分：用例字段结构

每条执行记录 = 测试项级字段 + 用例级字段，平铺合并：

| 字段 | 来源层级 | 说明 |
| --- | --- | --- |
| `url` | 接口级 | 拼全的完整地址 |
| `method` | 接口级 | 大写规范化的请求方法 |
| `headers` | 角色级 | 查表得到的整头（含 token） |
| `sql_database` | 测试项级 | SQL 断言查询库名 |
| `CaseID` / `case_name` | 用例级 | 用例标识/名称（CaseID 作 pytest 用例 id） |
| `is_active` | 用例级 | Y/N，非 Y 在执行端 skip |
| `body` | 用例级 | 请求体原文 |
| `expected_status_code` | 用例级 | 状态码断言 |
| `assertions` | 用例级 | 断言表达式列表（含 set:/sql: 等内置前缀） |
| `description` | 用例级 | 用例描述 |

**关键点**：

- **每条用例自带全部执行所需信息**（URL、头、体、断言、库名）——执行端不需要再查数据库，用例文件可独立于平台运行。
- `is_active != 'Y'` 的用例照样下发，由执行端 `pytest.skip` 处理（见 08）——保证报告里能看到"跳过的用例"。

---

## 整体流程

1. dispatch_run 进入 type1 分支后调用 `build_test_item_cases(type1_ids, domain_obj.domain, env_obj.env, headers_map)`。
2. 逐测试项：取接口对象 → 拼全 URL → 按 `user_{role}_{system}` 查整头（缺则空头） → 逐用例平铺字段。
3. 返回 `all_cases`，长度回填 `test_run.total`。
4. 由 08 写入 `data/single_cases/{run_id}_cases.txt`，供 pytest 参数化消费。
