# 数据库设计（角色数据源）

## 实现内容

角色信息的"源头"由四部分组成：角色清单常量 `TEST_ROLES`、测试项上的 `role/system` 字段、按"环境×角色"维护的账号映射表 `DB_TestAccount`，以及提供登录域名与基础请求头模板的关联表。模型先后经历 4 次迁移演进：从"测试项绑账号 + 静态 token 表"重构为"测试项绑角色 + 执行时动态取 token"。

## 代码来源

- `api_app/models.py`
- `api_app/migrations/0024 ~ 0027`

---

## 第一部分：角色清单 TEST_ROLES

```py
# 测试角色清单（存储/脚本用英文；前端展示时映射回中文，固定 6 角色 × 3 环境 = 18 条）
TEST_ROLES = ['zhihui', 'exam', 'content', 'org', 'student', 'afterschool']
```

**关键点**：

- 全链路角色值的**单一数据源**：前端选项、DB_TestItem.role、请求头键名 `user_{角色}_{端}`、脚本变量名都以此为准。
- 存英文的原因：角色值要嵌进请求头键名（`user_zhihui_oss`）和 Python 字典键，中文键名在编码与兼容性上不可靠；中文只在展示层由 role_labels.js 映射。
- 常量放在 models.py 里，接口层（views）直接 `from api_app.models import TEST_ROLES` 引用。

## 第二部分：测试项表 DB_TestItem（角色相关字段）

```py
class DB_TestItem(models.Model):
    ...
    role = models.CharField('测试角色', max_length=50, blank=True, default='')
    system = models.CharField('测试端', max_length=10, blank=True, default='')
```

**关键点**：

- `role` 存英文角色值、`system` 存 oss/app，二者拼出请求头查表键 `user_{role}_{system}`。
- 仅单接口用例（type=1）使用这两个字段；多接口脚本保存时前端传空（脚本按需自取角色头）。
- 旧字段 `account_name`（直接绑具体账号）已被 0025 迁移删除。

## 第三部分：测试账号表 DB_TestAccount

```py
# 测试账号（按 环境+角色 维护映射；执行时按 环境+角色 解析用户名，批量获取 token）
class DB_TestAccount(models.Model):
    env = models.ForeignKey('DB_Env', verbose_name='测试环境', on_delete=models.SET_NULL, null=True, blank=True)
    role = models.CharField('角色', max_length=50, default='')
    username = models.CharField('测试用户名', max_length=100)
    is_del = models.BooleanField('是否删除', default=False)

    class Meta:
        verbose_name = '12_测试账号表'
        verbose_name_plural = '12_测试账号表'
        unique_together = ('env', 'role')
```

**关键点**：

- 唯一约束 `(env, role)`：同一环境下每个角色最多一个账号；不同角色**允许指向同一个账号**（实测种子中 org 与 student 共用 adminqwqwqw，token 值相同）。
- 容量模型：固定 6 角色 × 3 环境 = 18 条，由角色配置弹窗全量覆盖维护（见 02/03）。
- 只存"角色→用户名"映射，**不存 token**——token 在每次执行时动态获取（旧 DB_Token 表已废弃删除）。

```py

class DB_HeaderTemplate(models.Model):
```

## 第五部分：迁移演进（0024 → 0027）

| 迁移 | 动作 | 背景 |
|---|---|---|
| 0024 | 建 DB_TestAccount（env+username 唯一）；删 DB_Token；DB_TestItem 加 `account_name`/`system`；DB_Domain 加 `app_server`；DB_HeaderTemplate 加 `system` | 账号体系起步：账号绑定测试项、token 存表 |
| 0025 | DB_TestItem `account_name` → `role`；DB_TestAccount 加 `role`；唯一约束改为 `(env, role)`；**清空旧账号数据** | 核心重构：测试项从"绑账号"改为"绑角色" |
| 0026 | 角色值中→英（智慧→zhihui、机构→org、学生→student、托管→afterschool） | 统一英文存储，中英映射前移到展示层 |
| 0027 | DB_TestItem 加 `script_inputs`（多接口入参 JSON 文本） | 变量池种子的最高优先级来源（见 09） |

0026 的转换逻辑：

```py
# 角色值从中文改为英文（存储与脚本统一英文，前端展示时映射回中文）
# 智慧->zhihui、机构->org、学生->student、托管->afterschool；exam/content 原本即英文
ROLE_MAP = {'智慧': 'zhihui', '机构': 'org', '学生': 'student', '托管': 'afterschool'}

def to_english(apps, schema_editor):
    DB_TestItem = apps.get_model('api_app', 'DB_TestItem')
    DB_TestAccount = apps.get_model('api_app', 'DB_TestAccount')
    for old, new in ROLE_MAP.items():
        DB_TestItem.objects.filter(role=old).update(role=new)
        DB_TestAccount.objects.filter(role=old).update(role=new)
```

**关键点**：

- 0025 会**清空全部旧账号数据**（旧结构 环境+用户名 与 环境+角色 不兼容），迁移后由用户在弹窗重新录入 18 条。
- 0026 写了反向函数 `to_chinese`，支持 migrate 回退。
- migration 里用 `apps.get_model` 拿历史模型，不直接 import models.py 的当前类。

## 整体流程

1. `TEST_ROLES` 定义角色全集（英文），作为全链路单一数据源。
2. 测试项编辑时把 `role/system` 写入 DB_TestItem（单接口用例）。
3. 角色配置弹窗把"环境×角色→账号"全量写入 DB_TestAccount。
4. 执行时按 `env_id` 查 DB_TestAccount 得到 `{角色: 账号}`；DB_Env/DB_Domain/DB_HeaderTemplate 提供环境段、登录域名与请求头底版。
5. token 不再落库，每次执行动态获取。
