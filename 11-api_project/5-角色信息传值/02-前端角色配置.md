# 前端角色配置

## 实现内容

前端承担角色体系的"配置入口 + 展示映射"：`role_labels.js` 把英文角色值映射回中文展示；`TestItemList.vue` 在测试项编辑里提供角色**单选框组**（单接口用例）；`RunList.vue` 在执行面板提供"角色配置"弹窗，以**环境×角色矩阵**维护账号映射（全量提交）。底层与接口交互的数据一律是英文角色值。

## 第一部分：角色中英映射 role_labels.js

```js
// 角色英文值 → 中文显示（数据库与脚本统一存英文值，前端仅做展示映射）
export const ROLE_LABELS = {
    zhihui: '智慧',
    exam: 'exam',
    content: 'content',
    org: '机构',
    student: '学生',
    afterschool: '托管',
};

export function roleLabel(role) {
    return ROLE_LABELS[role] || role;
}
```

**关键点**：

- 全前端唯一的映射出口：所有要显示角色名的地方都调 `roleLabel(r)`，不再散落 `if role === 'zhihui'` 之类的判断。
- `|| role` 兜底：映射表没有的值原样显示（如新增角色时前端不至于空白）。
- `exam`、`content` 中英同形，仍保留在表里保证结构完整。

**回填与保存**：

```js
open_edit(item){

    role: d.role || 'exam',       // 详情回填，无值给默认

```

```js
// save_edit：多接口脚本不传角色字段
const payload = {
    ...

    system: isScript ? '' : this.edit_form.system,

```

**关键点**：

- 角色选项**不从本地硬编码**，而是调 `get_test_accounts` 拿后端 `TEST_ROLES`，保证单一数据源——后端加角色前端自动出现。
- 按用户要求用**单选框组**（非下拉），六个角色平铺一行，操作成本低。
- 多接口脚本（type=2）保存时 `role/system` 强制置空：脚本自己按需引用角色头，测试项不需要绑角色。
- radio 的 `:value="r"` 绑的是英文值，`v-model="edit_form.role"` 最终提交给后端的也是英文。

## 第三部分：执行面板——角色配置弹窗

**弹窗模板（行=环境，列=角色，格子=账号名）**：

```html
<!-- 角色配置弹窗：行=环境，列=角色，格子=账号名 -->
<div v-if="show_role_dialog" class="run-overlay" @click.self="show_role_dialog = false">
    <div class="run-dialog-box" style="width: 860px">

                    </td>
                </tr>
            </tbody>
        </table>
        ...
    </div>
</div>
```

**打开弹窗（初始化矩阵 + 回填已存账号）**：

```js
open_role_dialog(){
    axios.get('http://172.16.2.60:8000/get_test_accounts/').then(res => {
        this.roles = res.data.roles || [];
        // 先按 环境×角色 初始化空格子（保证 Vue2 响应式），再回填已保存账号
        const matrix = {};
        this.envs.forEach(e => {
            const row = {};
            this.roles.forEach(r => { row[r] = ''; });
            matrix[e.id] = row;
        });
        (res.data.accounts || []).forEach(a => {
            if (matrix[a.env_id] && a.role in matrix[a.env_id]) matrix[a.env_id][a.role] = a.username;
        });
        this.account_matrix = matrix;
        this.show_role_dialog = true;
    })
},
```

**关键点**：

- 矩阵用 `account_matrix[环境id][角色英文值] = 账号名` 的嵌套字典承载。
- **必须先全量初始化空格子再回填**：Vue2 对后加的属性不响应，直接对不存在的键赋值输入框会不可编辑。
- 回填时做双重存在性判断（`matrix[a.env_id]` 且 `a.role in matrix[...]`），后端存量数据有异常值也不会打崩页面。
- 角色列头显示中文（`roleLabel`），但矩阵 key、提交值全是英文。

## 第四部分：保存角色映射（全量提交）

```js
save_accounts(){
    // 全量提交（含空格子，后端过滤空用户名不落库）
    const accounts = [];
    this.envs.forEach(e => {
        this.roles.forEach(r => {
            accounts.push({env_id: e.id, role: r, username: (this.account_matrix[e.id] || {})[r] || ''});
        });
    });
    axios.post('http://172.16.2.60:8000/update_test_accounts/', {accounts}).then(res => {
        if (res.data.code === 0) {
            alert('保存成功，共 ' + res.data.count + ' 条映射');
            this.show_role_dialog = false;
        } else {
            alert(res.data.message || '保存失败');
        }
    }).catch(err => {
        alert('保存失败: ' + err.message);
    })
},
```

**关键点**：

- 提交结构是**环境×角色的全笛卡尔积**（3×6=18 条），空格子也提交（username 空串），由后端过滤——前端不做删除 diff，逻辑最简单。
- 保存成功提示里的 `count` 是后端实际落库条数（=非空格子数），可直观核对配了几个账号。
- 保存是**全量覆盖**语义（后端先清后建），所以弹窗每次打开都拉全量数据回填，不需要考虑增量状态。

## 整体流程

1. 页面挂载：TestItemList 调 `get_test_accounts` 拿英文角色列表，渲染单选组/矩阵列头（中文展示）。
2. 配账号：执行面板点"角色配置" → 弹窗初始化 环境×角色 矩阵并回填 → 用户填账号 → `save_accounts` 全量 POST → 后端先清后建。
3. 绑角色：测试项编辑（单接口用例）选角色、选测试端 → 保存进 DB_TestItem；多接口脚本不涉及。
4. 展示映射：所有界面显示角色名时统一走 `roleLabel()`，底层数据保持英文。
