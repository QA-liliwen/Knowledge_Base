# 脚本侧消费（resolve_refs 变量替换）

## 实现内容

录制生成的 pytest 脚本（示例：`3_test_recorded_api_sequence.py`）如何消费平台下发的变量池：启动时按脚本名读 `script_vars.json`（两级合并）→ 对请求定义里的占位符递归替换（整值引用 + 字符串内嵌）→ 发请求 → `extract` 回写变量供后续步骤引用。这是"角色传值"链路的最后一公里。

## 代码来源

`api_app/data/custom_scripts/3_test_recorded_api_sequence.py`（全文）

## 第一部分：请求定义中的占位符形态

```py
REQUESTS: list[dict[str, Any]] = [{'name': 'listExams',
  'group': 'recorded_api_flow',
  'url': "https://{'__var__': 'domain'}/qbank/{'__var__': 'env'}/exam/exam/listExams",
  'method': 'POST',
  'headers': {'__var__': 'user_exam_app'},
  'params': {},
  'json_data': {'classifyAlias': 'teach_material', 'page': 1, 'pageSize': 20, 'name': '', 'gradeId': 0},
  'data': None,
  'extract': [],
  'expected_status': 200},
 ...
]
```

**关键点**：

- 两种占位形态，都由录制器生成：
  1. **整值引用**：`{'__var__': 'user_exam_app'}`——整个 dict 就是一个引用（适合 headers 这种"要一整份头"的字段）；
  2. **字符串内嵌**：URL 字符串里嵌 `{'__var__': 'domain'}` / `{'__var__': 'env'}`（Python 源码中的字面内容）。
- 设计意图：录制时未知的值以占位符保留，执行时替换——**录制产物与执行环境解耦**，同一脚本可在任意环境跑。
- headers 直接引用 `user_exam_app` 键 → 拿到的就是 06/09 下发的整头——**脚本侧零拼装**（不用自己填 token/serverId 字段）。

## 第二部分：解析器 resolve_refs

```py
REF_KEY = "__var__"
# 字符串内嵌占位（URL 中）：{'__var__': '键'}
INLINE_REF_PATTERN = re.compile(r'''\{\s*['"]__var__['"]\s*:\s*['"]([^'"]+)['"]\s*\}''')


def resolve_refs(value: Any, variables: dict[str, Any]) -> Any:
    if isinstance(value, dict):
        if set(value) == {REF_KEY}:
            return variables[value[REF_KEY]]
        return {key: resolve_refs(child, variables) for key, child in value.items()}
    if isinstance(value, list):
        return [resolve_refs(child, variables) for child in value]
    if isinstance(value, str):
        # 字符串内嵌占位替换，未命中保留原样
        return INLINE_REF_PATTERN.sub(lambda m: str(variables.get(m.group(1), m.group(0))), value)
    return value
```

**关键点**：

- **整值引用判定**：`set(value) == {REF_KEY}` 即 dict 恰好只有 `__var__` 一个键；替换直接取 `variables[键]`——**未命中会 KeyError**（硬引用，整头必须存在；实际不下发会报错暴露，符合偏好）。
- **字符串内嵌替换**：正则匹配 `{'__var__': 'xxx'}`（容忍空格、单双引号），`variables.get(键, 原样)`——**未命中保留原占位文本**（软引用；URL 里留下字面量会请求失败，便于看出是哪个键没下发）。
- 递归处理 dict / list 任意层级：`headers`、`json_data`、`params` 深处都能替换；替换产出**新对象**不原地改。
- `REF_KEY`/`INLINE_REF_PATTERN` 是录制产物与平台之间的**协议常量**——平台侧（09 种子）只认键名约定，脚本侧只认占位形态，双方无需感知对方实现。

## 第三部分：变量池读取（两级合并）

```py
def test_recorded_api_sequence(recorded_session: requests.Session) -> None:
    # 变量池：平台执行前注入同目录 script_vars.json（按脚本文件名索引）
    # 两级结构：__common__ 公共层（domain/env/全量头）全执行一份 + 本脚本入参层，合并后入参最高优先级；
    # 兼容旧格式（无 __common__ 键时本层即完整种子）
    with open(os.path.join(os.path.dirname(os.path.abspath(__file__)), "script_vars.json"), encoding="utf-8") as f:
        _vars_data = json.load(f)
    variables: dict[str, Any] = {**(_vars_data.get('__common__') or {}), **(_vars_data.get(os.path.basename(__file__)) or {})}
```

**关键点**：

- 读取契约三点一线：**同目录 `script_vars.json`**（10 落地位置）+ **`os.path.basename(__file__)` 索引**（09 种子键 `test_flow_{id}.py`）+ 脚本落地文件名 `test_flow_{item_id}.py`（10 复制/打包命名）。
- **两级合并**：`{**common, **own}`——`__common__` 公共层（domain/env/全量头，09 篇全执行只存一份）打底、本脚本入参层覆盖，同名键以**入参为准（最高优先级）**。
- **向后兼容旧格式**：旧种子无 `__common__` 键 → common 为空 dict → 合并结果 = own 本身（旧格式的 own 就是完整种子），行为完全不变——平台与脚本可异步升级、不断档。
- 双 `or {}` 兜底：种子缺本脚本键 / 键值为 null → 空池不报错（占位符保持原样、请求失败暴露）——"不拦截、自然失败"风格与 token 降级一致。
- 多脚本共享一个种子文件、各取"公共层 + 自己那份"，互不影响。
- URL 用 `os.path.dirname(os.path.abspath(__file__))` 拼——脚本被复制到 `custom_runs/{run_id}/`（或 zip 解压目录）后，永远读的是**执行现场同目录**的种子文件。

## 第四部分：请求发送与 extract 回写

```py
    for index, request_item in enumerate(REQUESTS, start=1):
        method = request_item["method"].upper()
        url = resolve_refs(request_item["url"], variables)
        response = recorded_session.request(
            method=method,
            url=url,
            headers=resolve_refs(deepcopy(request_item.get("headers") or {}), variables),
            params=resolve_refs(deepcopy(request_item.get("params") or {}), variables),
            json=resolve_refs(deepcopy(request_item.get("json_data")), variables),
            data=resolve_refs(deepcopy(request_item.get("data")), variables),
            timeout=float(os.getenv("RECORDER_TIMEOUT", "30")),
        )

        expected_status = int(request_item.get("expected_status") or 200)
        assert response.status_code == expected_status, (
            f"{step_label(index, request_item)} {method} {url} returned {response.status_code}, "
            f"expected {expected_status}; response={response.text[:2000]}"
        )

        response_json = response_json_or_none(response)
        for extractor in request_item.get("extract", []):
            assert response_json is not None, (
                f"{step_label(index, request_item)} has extractors but response is not JSON"
            )
            variables[extractor["name"]] = get_json_path(
                response_json, extractor["path"]
            )
```

**关键点**：

- **headers 替换前 deepcopy**：避免替换产物污染 `REQUESTS` 原定义（同一引用被多处使用时安全）。
- 取值链：`url` 做 begin 替换 → `headers` 整头引用解析 → body/params/data 递归替换 → session 发请求。
- **步骤间变量传递**：本步骤 `extract`（JSONPath 取响应值）写回 `variables`，后续步骤的占位符即可引用 `{'__var__': '提取的键'}`——多接口串联（如 A 接口建题返回 id、B 接口用 id 提交）的核心机制。
- 失败信息含步骤名/URL/响应前 2000 字符——**变量没替换对（URL 里残留 `{'__var__'...}` 字面量）时一眼能看出来**。
- `session` 复用：同一账号的头部跨步骤复用连接；每脚本独立 fixture（`recorded_session`），可与其他脚本共存。

## 整体流程

1. pytest 启动脚本 → 读同目录 `script_vars.json`，两级合并（`__common__` 公共层 + 本脚本入参层）得到自己的变量池。
2. 逐步骤：`resolve_refs` 替换 url / headers / params / json_data / data → 发请求 → 断言状态码。
3. `extract` 提取响应值回写 `variables` → 供后续步骤引用。
4. 用例通过/失败由 pytest 输出落盘，终态 conftest 回调平台（见 12）。
