# 多接口变量池种子（script_vars 组装）

## 实现内容

dispatch_run 的 type2 分支前半段（L174-189）：组装变量池种子 `script_vars`，**两级结构**——`__common__` 公共层（domain/env + 全量角色头）全执行只存一份，各脚本键（`test_flow_{item.id}.py`）下只放该项自己的入参；脚本读取时 `{**common, **own}` 合并（入参最高优先级，见 11）。差异点：单接口是"按测试项查表取一份头"，多接口是"全量表直接下发、脚本自由引用"。

## 代码来源

`api_app/api_test/api_executor.py`（type2 分支 L174-189）

---

## 第一部分：common_vars 公共层

```py
    # 执行多接口脚本
    if type2_ids:
        # 组装脚本变量池种子（两级结构）：__common__ 公共层（domain/env + 全量头 user_{角色}_{端}）全执行只存一份，
        # 各脚本键下只放该项自己的入参；脚本读取时 {**common, **own} 合并 → 入参仍为最高优先级
        common_vars = {'domain': domain_obj.domain, 'env': env_obj.env, **headers_map}
        script_vars = {'__common__': common_vars}
```

**关键点**：

- 公共层内容：`domain`/`env`（字符串段，脚本 URL 模板用）+ `headers_map` 展开（06 产物的全部 `user_*_*` 键）。
- **全执行只存一份**：公共数据（12 个头的 token 等）不再随脚本数平铺复制——N 个脚本执行，种子只含一份公共层 + N 份入参（优化前是 N 份完整种子，冗余随脚本数线性放大）。
- `headers_map` **整表嵌入**、不做按测试项筛选：变量池天生就是"全量可引用"语义——脚本可以引用任意角色、任意端的头（多接口场景常见"步骤1用 exam 发题、步骤2用 student 答题"）。
- `__common__` 键名与 `__var__` 协议的双下划线风格一致；落地脚本名固定 `test_flow_{id}.py`，永不冲突。

## 第二部分：逐脚本入参层

```py
        for item in test_items:
            if item.type != 2:
                continue
            try:
                inputs = json.loads(item.script_inputs) if item.script_inputs else {}
            except json.JSONDecodeError:
                inputs = {}
            if not isinstance(inputs, dict):
                inputs = {}
            script_vars[f"test_flow_{item.id}.py"] = inputs
```

**关键点**：

- 种子键 = `test_flow_{item.id}.py`：与 10 篇落地时脚本文件名（本地复制为 `test_flow_{item_id}.py`、zip 内同名）**严格一致**；脚本侧用 `os.path.basename(__file__)` 反查自己那份（见 11）。
- **合并时机后移**：平台只下发两层原始数据，`{**common, **own}` 合并发生在**脚本读取时**——同名键仍以入参为准（最高优先级），脚本作者可用入参覆盖平台注入值（比如脚本要打另一个域名）。
- 容错三连：`script_inputs` 为空 → 空 dict；非法 JSON → `JSONDecodeError` 捕获降级空 dict；解析出非 dict → 强制空 dict。配置坏不炸执行。
- 循环里用 `continue` 跳过 type1（本次执行可单/多接口混合提交，两类各自成组）。
- **向后兼容在读取端天然成立**（见 11）：旧格式种子无 `__common__` 键 → 公共层为空 → 合并结果 = own 本身，行为不变。

## 第三部分：真实种子样例

**新格式（两级结构）**——公共层一份 + 各脚本入参层：

```json
{
  "__common__": {
    "domain": "devapi1.lingshi.com",
    "env": "vs2",
    "user_zhihui_oss": { "token": "", "serverid": "" },
    "user_exam_oss": { "token": "462821:……（省略）……:1201v", "serverid": "1201" },
    "user_exam_app": { "DeviceUniqueId": "d91ed0b9-…（省略）…", "serverId": "1201", "token": "462821:……（省略）……:1201v" },
    "...": "该环境全部角色 × 2 端的头（run 114 时点为 12 个）"
  },
  "test_flow_3.py": { "自定义入参": "..." },
  "test_flow_7.py": {}
}
```

**旧格式（优化前，run 114 实测）**——公共种子对每个脚本全量平铺复制：

```json
{
  "test_flow_3.py": {
    "domain": "devapi1.lingshi.com",
    "env": "vs2",
    "user_zhihui_oss": { "token": "", "serverid": "" },
    "user_org_oss": { "token": "30956:……（省略）……:1203v", "serverid": "1203" },
    "...": "12 个头全量平铺在该脚本键下，每个脚本重复一份"
  }
}
```

**观察结论**（数据特性对新旧格式均成立）：

- **12 个头全量下发**（该环境配置了 6 个角色 × 2 端），不是只发脚本用到的；新格式下归拢在 `__common__` 一处。
- 每个头 = 06 预组装产物的**原样**：oss = `{token, serverid}`、app = `{DeviceUniqueId, serverId, token}`。
- **token 为空的键照样保留结构**（zhihui/afterschool 两端、org/student 的 app 端）——脚本引用到就拿到空 token 的头，请求自然 401，失败可见。
- **org 与 student 共用账号**：两端 token 值完全相同（`30956:…:1203v` 同值同 serverid）——账号去重取一次 token，多角色共享结果。
- serverId 与 token 末段对应（exam/content=1201、org/student=1203）——06 篇"从 token 末段动态提取 serverId"在种子中可直接验证。
- 顶层 `domain`/`env` 公共键——脚本 URL 模板 `https://{'__var__': 'domain'}/qbank/{'__var__': 'env'}/...` 靠它们拼全（见 11）。

## 整体流程

1. `common_vars = {'domain': …, 'env': …, **headers_map}`（头表整表下发），存入 `__common__` 公共层（全执行一份）。
2. 遍历选中测试项，跳过 type1；读每个 type2 测试项的 `script_inputs`（用户填的入参 JSON，容错解析），以 `test_flow_{item.id}.py` 为键只放入参层。
3. 按 `run_mode` 交给 `run_custom`（本地）或 `run_custom_jenkins`（Jenkins）落地（见 10）。
4. 脚本读取时 `{**__common__, **own}` 合并成自己的变量池（入参最高优先级，见 11）。
