# api_local_custom_runner.py

## 实现内容

`api_local_custom_runner.py` 负责在本地执行多接口脚本测试项。核心逻辑：创建执行记录 → 创建临时目录 → 复制各测试项脚本 → 写入 conftest.py → 启动 pytest 子进程。

## 代码来源

`api_app/api_test/api_local_custom_runner.py`

---

## 第一部分：创建执行记录

```py
def run_custom(test_item_ids, description, base_url, env=''):
    """执行多接口脚本测试项：写临时文件 → pytest 执行 → 回调平台"""
    started_ts = time.time()

    # 创建执行记录
    test_run = DB_run_result.objects.create(
        env=env,
        status="running",
        description=description,
        test_items=','.join(str(i) for i in test_item_ids),
        started_at=timezone.now(),
        trigger_source="local",
        total=len(test_item_ids),
    )
```

**关键点**：

- `test_items` 字段存的是逗号分隔的测试项 id 字符串，而非外键数组。
- `trigger_source="local"` 区分本次是本地执行还是 Jenkins 触发。
- `started_ts` 记录 Python 进程启动时间戳，后续传给 pytest 计算耗时。

## 第二部分：创建临时执行目录

```py
    # 创建本次执行的临时目录（放在项目根目录下，避免加载父目录 conftest）
    run_dir = os.path.join(PROJECT_ROOT, "custom_runs", str(test_run.id))
    os.makedirs(run_dir, exist_ok=True)
```

**关键点**：

- 临时目录路径：`{项目根目录}/custom_runs/{run_id}/`。
- 放在项目根目录而不是 `api_test` 目录下，是为了避免 pytest 扫描时加载项目自身的 conftest.py 产生干扰。
- 每次执行用独立目录，以 run_id 命名，方便清理和追溯。

---

## 第三部分：复制测试项脚本

```py
    # 将每个测试项的脚本文件复制到执行目录
    try:
        for item_id in test_item_ids:
            test_item = DB_TestItem.objects.get(id=item_id)
            if not test_item.script_filename:
                raise ValueError(f"测试项 {item_id} 未上传脚本文件")
            src_path = os.path.join(SCRIPTS_DIR, test_item.script_filename)
            if not os.path.exists(src_path):
                raise FileNotFoundError(f"脚本文件不存在: {test_item.script_filename}")
            dst_name = f"test_flow_{item_id}.py"
            dst_path = os.path.join(run_dir, dst_name)
            with open(src_path, "r", encoding="utf-8") as f:
                content = f.read()
            with open(dst_path, "w", encoding="utf-8") as f:
                f.write(content)
    except Exception as e:
        test_run.status = "failed"
        test_run.save()
        return {"code": -1, "message": str(e)}, 400
```

**关键点**：

- 每个测试项脚本从 `data/scripts/{script_filename}` 读取，写入临时目录并重命名为 `test_flow_{item_id}.py`。
- 重命名加上 `test_flow_` 前缀，让 pytest 能按 `test_*.py` 规则扫描到。
- 复制前先校验：脚本文件名不为空、源文件存在，任一步失败则将执行记录标记 failed 并返回错误。

## 第四部分：写入 conftest.py

```py
    # 写入 conftest.py（用于跑完后回调平台）
    with open(os.path.join(BASE_DIR, "conftest.py"), "r", encoding="utf-8") as f:
        conftest_content = f.read()
    with open(os.path.join(run_dir, "conftest.py"), "w", encoding="utf-8") as f:
        f.write(conftest_content)
```

**关键点**：

- 从 `api_test/conftest.py` 读取内容，写入本次执行的临时目录。
- conftest.py 中包含 `pytest_terminal_summary` 钩子，pytest 执行完毕后会回调平台更新执行结果。
- 必须显式复制，而不是依赖 pytest 查找父目录的 conftest，因为临时目录放在项目根目录下，不在 api_test 路径内。

---

## 第五部分：设置环境变量与文件路径

```py
    # 设置环境变量
    pytest_env = os.environ.copy()
    pytest_env["TEST_RUN_ID"] = str(test_run.id)
    pytest_env["BASE_URL"] = base_url
    pytest_env["STARTED_AT"] = str(started_ts)

    # 日志文件路径
    log_file_name = f"{test_run.id}_app.log"
    test_run.log_file = log_file_name
    test_run.save()
    pytest_env["LOG_FILE_NAME"] = log_file_name

    report_file = f"report_{test_run.id}.xml"
    test_run.report_file = report_file
    test_run.save()
```

**关键点**：

- 复制一份 `os.environ` 作为子进程环境，避免污染父进程。
- 传入 4 个关键环境变量：`TEST_RUN_ID`、`BASE_URL`、`STARTED_AT`、`LOG_FILE_NAME`，供 pytest 脚本读取。
- 日志和报告文件名写入 `test_run` 记录，前端后续根据这两个字段提供下载链接。

---

## 第六部分：启动 pytest 子进程

```py
    # 启动 pytest
    subprocess.Popen(
        ["pytest", run_dir, "-v", f"--junitxml={os.path.join(run_dir, report_file)}"],
        env=pytest_env,
        cwd=run_dir,
    )

    return {"code": 0, "message": "success", "run_id": test_run.id}, 200
```

**关键点**：

- 使用 `Popen` 非阻塞启动，Django 进程立即返回 run_id，不等待 pytest 执行完成。
- pytest 扫描整个 `run_dir`，自动发现所有 `test_flow_*.py` 文件。
- `--junitxml` 生成 JUnit XML 报告，前端结果页可通过下载链接获取。
- `cwd=run_dir` 让 pytest 以临时目录为工作目录，保证 conftest.py 被正确加载。

---

## 整体流程

1. 创建 `DB_run_result` 记录，状态 running。
2. 创建 `custom_runs/{run_id}/` 临时目录。
3. 逐个复制测试项脚本，重命名为 `test_flow_{id}.py`。
4. 复制 conftest.py 到临时目录。
5. 设置环境变量，记录日志和报告文件名。
6. Popen 非阻塞启动 pytest → 立即返回 run_id。
7. pytest 执行完毕后 conftest.py 回调平台更新结果。
