## 一、数据层（api_app/models.py）

### DB_SqlEnv：SQL 连接表（只管连接，不管库）

```py
# SQL 连接配置
class DB_SqlEnv(models.Model):
    env_name = models.CharField('环境名称', max_length=50, unique=True)  # 与 DB_Domain.domain 对应，如 devapi1.lingshi.com
    host = models.CharField('主机', max_length=200)
    port = models.IntegerField('端口', default=3306)
    user = models.CharField('账号', max_length=100)
    password = models.CharField('密码', max_length=200)
    is_del = models.BooleanField('是否删除', default=False)

    class Meta:
        verbose_name = '10_SQL连接表'
        verbose_name_plural = '10_SQL连接表'

    def __str__(self):
        return f"{self.env_name} {self.host}:{self.port}"
```

**解释**：
- 一条记录 = 一个域名的数据库连接方式。目前配了两条：devapi1.lingshi.com（测试）、preapi1.lingshi.com（预发）
- 生产域名（api1.lingshi.com）故意不配 → 执行时查不到 → SQL 断言自动跳过，物理隔离生产库
- **关联键是域名而不是环境名**：同一个测试环境（vs2）下，不同域名连不同的库，SQL 连接跟着域名走

## 三、执行链路注入（api_test/）

### dispatch_run 查连接（api_executor.py）

```py
# 按 DB_Domain.domain 查 SQL 连接配置（如 devapi1.lingshi.com，未配置 = 忽略所有 sql: 断言）
sql_conn = None
sql_env = DB_SqlEnv.objects.filter(env_name=domain_obj.domain, is_del=False).first()
if sql_env:
    sql_conn = {
        'DB_HOST': sql_env.host,
        'DB_PORT': str(sql_env.port),
        'DB_USER': sql_env.user,
        'DB_PASSWORD': sql_env.password,
    }
```

**解释**：执行调度时按选中域名查 SQL 连接，查到组装成「环境变量字典」`sql_conn`，查不到保持 None。注意 DB_PORT 转 str——环境变量值一律用字符串。

**关键点**：查找键是 `domain_obj.domain`。这里曾踩坑：先按 `DB_Env.env`（vs2）查，实际配置存的是域名，永远查不到 → SQL 断言全部静默跳过。

### build_test_item_cases 带库名（api_executor.py）

```py
all_cases.append({
    ...
    'assertions': case['assertions'],
    'description': case['description'],
    'sql_database': test_item.sql_database,  # SQL 断言查询库名
})
```

**解释**：库名在组装用例时就写进每条 case，跟着 cases JSON 一起落盘（`{run_id}_cases.txt`）、一起打进 Jenkins zip。执行侧（pytest）不需要回查数据库。

### 本地执行注入（api_local_single_runner.py）

```py
def run_single_local(test_run, cases_txt_path, sql_conn=None):
    ...
    pytest_env = os.environ.copy()
    pytest_env["TEST_RUN_ID"] = str(test_run.id)
    pytest_env["LOG_FILE_NAME"] = log_file_name
    pytest_env['STARTED_AT'] = str(started_ts)
    # SQL 断言连接四要素（未配置则不注入，sql: 断言自动跳过）
    if sql_conn:
        for key, value in sql_conn.items():
            pytest_env[key] = value
    subprocess.Popen(
        ["pytest", os.path.join(BASE_DIR, "run_request.py"), "-v", f"--cases-file={cases_txt_path}"],
        env=pytest_env,
        cwd=BASE_DIR,
    )
```

**解释**：sql_conn 非空时把 DB_HOST/DB_PORT/DB_USER/DB_PASSWORD 注入 pytest 子进程环境变量。不注入时执行器读不到 → 自动跳过，本地和 Jenkins 是同一条判断代码。

### Jenkins 执行注入（api_jenkins_single_runner.py）

```py
def trigger_jenkins_build(zip_bytes, run_id, base_url, sql_conn=None):
    ...
    data = {
        'RUN_ID': str(run_id),
        'BASE_URL': base_url,
        crumb_field: crumb_value,  # 同时作为表单字段
    }
    # SQL 断言连接四要素（Jenkins job 需声明同名 4 个参数）
    if sql_conn:
        data.update(sql_conn)
```

**解释**：四要素加进 buildWithParameters 的表单参数，Jenkins job 侧用 `%DB_HOST%` 等环境变量透传给 pytest。

**关键点**：
- Jenkins job 需要预先声明 DB_HOST / DB_PORT / DB_USER / DB_PASSWORD 四个参数（Job 配置页一次性操作），否则参数传不过去
- 多接口脚本执行器（run_custom_jenkins）不传 sql_conn，走默认 None，不受影响

### Jenkins 打包带上执行器（api_jenkins_single_runner.py）

```py
# 读取 sql_assert.py 文件（SQL 断言执行器，run_request.py 依赖它）
with open(os.path.join(BASE_DIR, "sql_assert.py"), "r", encoding="utf-8") as f:
    sql_assert_content = f.read()

with zipfile.ZipFile(buf, 'w', zipfile.ZIP_DEFLATED) as zf:
    zf.writestr("conftest.py", conftest_content)
    zf.writestr("run_request.py", run_request_content)
    zf.writestr("sql_assert.py", sql_assert_content)   # 新增
    zf.writestr("log_config.py", build_jenkins_log_config())
    zf.writestr("requirements.txt", "requests\npytest\npytest-html\npymysql\n")  # pymysql 新增
    ...
```

**关键点**：
- run_request.py `from sql_assert import ...` 依赖同目录的 sql_assert.py，zip 不带上它 Jenkins 端直接 ImportError——这是最容易漏的一处
- requirements.txt 由代码生成（字符串拼接），加依赖要改这里而不是装本地环境

## 四、数据流总览

```
RunList 选域名(devapi1) ──→ DB_SqlEnv 查连接 ──→ sql_conn(四要素)
                                    │
测试项.sql_database ──→ build_test_item_cases ──→ 每条 case 带 sql_database
                                    │
本地: pytest_env 注入四要素          Jenkins: 表单参数传四要素
              └──────────┬──────────┘
                    pytest 子进程 os.environ
                         ↓
              run_request.py 断言引擎
```

**执行后行为**：无 sql_conn（域名没配）或 case 无 sql_database（测试项没配）→ sql: 断言记日志跳过，用例照常执行其余断言。
